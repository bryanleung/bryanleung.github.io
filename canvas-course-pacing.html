Course Pacing Redesign

I redesigned Course Pacing so instructors can set a pace for each section and each student, not only for the whole course.

Product
Canvas LMS
Role
Senior Designer
Team
1 product manager, 6 engineers
Scope
Design, research
Year
2023

Summary

Problem
Course Pacing could only pace a whole course. Instructors said that made it unusable, and usage was very low.
Role
Only designer, with one product manager and six engineers. Design, research and support through the build.
Solution
Sections and Students tabs, a full-screen view for each pace, blackout dates and pending changes.
Result
Released to beta. Instructors were glad to set custom paces. We set no clear measure of success.

The problem

In a rolling-enrollment course, students start on different dates, so every due date differs by student. Instructors entered them by hand, and again for every extension.

Course Pacing calculates the dates from a pace. Its first version set one pace for the whole course.

The feature is essentially useless to me unless I can set paces for my students individually.

What made it hard:

  • Scale. The dropdown for switching between sections and students stops working past about 25 students.
  • Three levels. A course, a section and a student can each have a pace.
  • No documentation. The first version's design decisions weren't written down. The engineers who built it were the best source.

Design decisions

Tabs in place of a dropdown

I explored several directions and chose the one that fit our time and technical constraints. Sections and Students each get a tab, so a large course is a list to scan.

A full-screen view for each pace

Selecting a section or student opens its pace full screen.

A page that says where you are

A title, a one-line description, and more prominent stats and default pace. The original had no title.

Added in the same release

  • Blackout dates, so nothing falls due inside a set date range.
  • A way to view and reset pending changes.

Open the Course Pacing prototype in Figma

Validation and delivery

  • Testing. Three moderated tests with administrators at US universities, plus surveys. Overall sentiment favored the selected design.
  • Accessibility. Reviewed with our accessibility engineers for screen reader and keyboard focus issues.
  • Build. Several sprints. I answered usability and accessibility questions and proposed alternatives when something couldn't be built as designed.

Outcome

  • The redesign went to beta together with the new features.
  • Instructors were glad to set custom paces for their students.
  • We never set a clear measure of success. More paces created was treated as enough.

Reflection

  • I would agree on the success measure first, and count section and student paces separately from course paces. Without that, I can't put a number on the result.
  • Adjusting the duration of individual items is still inefficient. I wanted to redesign it and met significant resistance.
